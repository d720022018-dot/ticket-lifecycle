<h1>osTicket - Ticket Lifecycle: Intake Through Resolution</h1>
This tutorial outlines the lifecycle of a ticket from intake to resolution within the open-source help desk ticketing system osTicket.<br />

<h2>Environments and Technologies Used</h2>

- Microsoft Azure (Virtual Machines/Compute)
- Remote Desktop
- Internet Information Services (IIS)
- osTicket

<h2>Operating Systems Used </h2>

- Windows 11</b> (24H2)

<h2>Ticket Lifecycle Stages</h2>

- Intake
- Assignment and Communication
- Working the Issue
- Resolution

<h2>Lifecycle Stages</h2>

<p>
The intake stage is the process of creating a support ticket and entering it into the ticketing system. In a real-world environment, tickets may be created in several ways, including a user submitting a ticket through a web portal, sending an email, using a chat application, calling the help desk, or speaking directly with an IT technician. In this lab, the ticket was created through an email. The image above shows how the ticket was created and put into the system.
</p>

<p>
After a ticket has been created and received by the help desk, it must be reviewed, prioritized, assigned to the appropriate technician or department, and communicated to the user. For this example, a user reports that their desktop computer will not power on because the power supply has failed. In the image above I changed the priority level to low and changed the SLA plan to Sev-C which means it needs to be resolved in 3 to 5 business days. I did this because the user had another computer they could use till the issue was resolved and it was not an imeadiate danger to the businees.
